# Qoo（Jam）— 訪日ソロトラベラー向け Tips 共有アプリ

「ディープな日本を、迷わず楽しむ」をテーマにした、訪日ソロトラベラー向けの Flutter 製 Web アプリです。
既存アプリのような「探す」情報や店舗の「評価」ではなく、現場で迷わず「立ち回る」ための Tips に特化しています。

**公開URL**: https://qooo-f4816.web.app

---

## コンセプト

見知らぬ誰かの「気遣い」が一人旅の心細さを埋め、助けられた旅人が次の旅人を助ける——
そんな温かい恩送りの循環を、Tips 共有・地域コレクション・多言語対応を通じて実現します。

---

## なぜこの機能を作ったのか

### 地域コレクション
旅行先を歩きながら新しいお店やスポットを発見したい旅行者に、ゲーム感覚で地域を巡るきっかけを作るため。同時に、店舗側にも「登録すると旅行者に見つけてもらえる」というメリットを持たせ、旅行者と地域のお店の両方が参加したくなる仕組みを目指しました。

### トイレ・ゴミ箱マップ
海外からの旅行者が特に困りやすい「トイレやゴミ箱が見つからない」悩みを解決するため。日本は公共のゴミ箱が少なく公開地図にもデータがほとんど無いため、旅行者同士が投稿し合って情報を育てる仕組みにしました。

### 多言語対応
訪日外客数の約8割をカバーする6言語に自動翻訳することで、言語の壁で情報が届かない問題を解消するため。

### ガチャ機能
「情報を投稿する」「街を巡る」という行動を、報酬を通じて自然に促すため。楽しみながら地域に関わってもらう動機づけを担います。

## 主な機能

### Tips 共有・マップ表示
現場で助かった情報を Tips として投稿し、地図上にピン表示。カテゴリ絞り込み・検索・「参考になった」に対応。

### 旅行写真
アプリ内カメラ／アルバムから写真を投稿。現在地に紐づいて地図に表示され、同じ場所の写真はグループ化。友達限定/全体公開を選べます。

### 地域コレクション
福岡のスポットやお店を巡って写真を集める、スタンプ帳のような機能。
- テーマ別コレクション（例：天神エリア制覇、グルメ巡り）で達成状況を可視化
- 承認済み店舗をカテゴリ別コレクションに自動反映
- 「みんなのコレクション」で他ユーザーの達成シートを閲覧・いいね

### 店舗からの情報発信
店舗が独自ルールやマナー（タトゥー・喫煙禁止など）や店舗情報を発信。登録申請 → 運営承認で掲載されます。

### ローカルルール（Local Hack）
神社の参拝作法、屋台・ラーメンのマナーなど地域固有のルールを地図上で発信。運営が投稿フォームから追加できます。

### トイレ・ゴミ箱マップ
OpenStreetMap の公開データ＋ユーザー投稿を合わせて、近くのトイレ・ゴミ箱を表示。Tips 投稿時にチェックひとつで登録できます。

### ガチャ機能
Tips 投稿や街巡りで貯めたコインでガチャを回し、アバター・フレーム・マーカースキンなどのアイテムを獲得・装備できます。

### 多言語対応（自動翻訳）
Cloud Translation API により、投稿・UI・観光ガイドを6言語（日本語・英語・韓国語・繁体字中国語・簡体字中国語・タイ語）に自動翻訳。翻訳結果は端末にキャッシュ。

## その他の機能

- **ログイン / 新規登録**：Firebase Authentication（メール/パスワード）
- **友達機能**：フレンドコードで友達追加、写真の限定公開
- **近くのお知らせ**：現在地周辺の Tips・ルール・お店の件数を通知
- **保存機能**：気になったスポットをブックマーク
- **通報機能**：不適切な投稿を運営に報告
- **運営ページ**：店舗承認・ローカルルール投稿を管理

## 技術構成

| 領域 | 使用技術 |
|------|----------|
| フロントエンド | Flutter（Web） |
| 地図・位置情報 | flutter_map + OpenStreetMap、Geolocator（3分ごと自動更新） |
| 認証 | Firebase Authentication（メール/パスワード） |
| データベース | Cloud Firestore |
| 画像保存 | Cloudinary |
| 翻訳 | Google Cloud Translation API |
| 施設データ | Overpass API（OSM のトイレ・ゴミ箱） |
| ホスティング | Firebase Hosting |

### 技術選定の理由
初心者中心のチーム構成のため、サーバーサイドのコードを書かず、クライアントから直接 Firestore を呼び出す構成にしました。複雑な集計やリレーショナルなクエリが不要な要件だったため、開発スピードと運用のしやすさを重視して Supabase ではなく Firebase を採用しています。言語も Dart に統一し、他言語の組み合わせによる実装・デプロイの複雑化を避けました。画像は Firebase Storage が無料プランで利用できないため、Cloudinary を採用しています。

## セットアップ

```bash
flutter pub get
flutter run -d chrome
```

翻訳機能を使う場合は、プロジェクトルートに `.env` を作成し、Cloud Translation API キーを設定してください。
TRANSLATION_API_KEY=your_api_key

### デプロイ

```bash
flutter build web
firebase deploy --only hosting
```
